Security Architecture & Controls

Specification of cloud security mechanisms planned for Amazon Web Services (AWS) deployment.

Architecture Target • Simulated Controls

Zero Direct Public S3 Bucket Access

In this application architecture, all client file traffic passes strictly through short-lived presigned URLs or authenticated AWS Lambda proxy handlers. The S3 bucket maintains strict "Block Public Access" policies.

S3 Target

Private Storage

Amazon S3 Bucket Policy blocks all anonymous read/write operations. Objects are segmented per tenant/user prefix (`uploads/{user_id}/`).

Enforcement: Bucket Policy Ready
AES-256 KMS

Server-Side Encryption

Data at rest is protected with AES-256 envelope encryption via AWS Key Management Service (AWS KMS) or SSE-S3 default bucket encryption.

Key Rotation: Enabled Ready
Cognito JWT

Identity & Authentication

AWS Cognito User Pools provide OAuth 2.0 / OpenID Connect authentication. JWT tokens validate client requests at API Gateway Lambda authorizers.

MFA: TOTP Enforced Integration Ready
TTL 5–60 min

Temporary Link Sharing

Amazon S3 Pre-signed GET URLs restrict download access to a defined duration (5 to 60 minutes). Expired URLs are automatically rejected by AWS.

Signed By: Lambda IAM Simulated in UI
Least Privilege

Granular Access Control

IAM execution roles define strict permissions for Lambda functions (e.g., `s3:PutObject`, `s3:GetObject`). Browser JavaScript holds zero IAM credentials.

Roles: Scoped per Service Designed
CloudWatch

Audit Logging & Traceability

AWS CloudTrail records S3 management and data events. Lambda emits structured operational logs into Amazon CloudWatch Logs for audit compliance.

Retention: 365 Days Ready
